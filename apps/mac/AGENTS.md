# ReLife for Mac

A native SwiftUI menu bar and window app that is a client of a ReLife server (plan:
`.plans/v1-relife-ecosystem.md`, Part 1 section 4 and Part 2 "Native Mac app"). It keeps no game rules of its
own: the server decides, the app shows Today, sends quick logs and check-offs, and reports which app is in front.
Bundle id `com.relife.mac`.

## Layout

- `Sources/ReLifeKit/` Foundation only (it builds and tests on Linux): `API/` (Codable twins of `packages/contract`,
  `ReLifeClient`, SSE parser, backoff), `Offline/` (queue rules, flusher), `Activity/` (segmenter), `Links/`
  (server address, connect code, `relife://` links), `Today/` (glance text, change detection, optimistic updates).
  `Brand.swift` is generated by `packages/brand/swift.mjs` (`npm run brand:swift`; `brand:check` fails when stale).
  Tests in `Tests/ReLifeKitTests/` read `packages/contract/fixtures` directly (via `#filePath`); there is no copy.
- `Sources/ReLife/` the app (macOS only). `Model/` has `AppModel` (the one observable model), pairing, the app
  watcher, the global hotkey, Keychain, local-server panel, notifier, SwiftData store, prefs. `Views/` has the window,
  menu bar window, quick log panel, onboarding, Settings. `UI/Tokens.swift` is generated by `packages/tokens`;
  do not edit it by hand.
- `build.sh` builds, signs and installs `~/Applications/<app name>.app`. There is no Xcode project. The app name is
  read once from `Brand.swift` by `tools/env.sh`, which `build.sh` and the other tools source; `Info.plist.in` takes it
  as `__APP_NAME__`. Do not type the product name in scripts, strings or comments (`npm run brand:check` guards it).

## Build and check

- `./build.sh` (add `--open` to restart). Fix every warning.
- `swift test --scratch-path ~/Library/Developer/ReLife/test-build` (also runs on Linux for ReLifeKit).
- `tools/selftest.sh` runs the app's real functions on a `/tmp` store. Set `APP_HEADLESS=1` on a machine with no
  logged-in user.
- `tools/snap.sh` takes real-window light and dark snapshots with `screencapture` (needs a screen).
- `tools/render.sh` draws every page, state, panel and onboarding step in light and dark with `ImageRenderer` and
  needs no screen. AppKit-backed controls are replaced by static stand-ins while `APP_RENDER` is set
  (`PageScroll`, `InputField`, `Spinner`, `SwitchRow`, `.linkButton()` in `UI/Components.swift`); system chrome is not drawn.
- `tools/grid-lint.sh` checks spacing numbers.
- `tools/fleet-buildspec.yml` runs all of the above on the remote macOS fleet (see the ios-testing skill; its header says
  how to stage `apps/mac` plus `packages/contract/fixtures`).
- Env modes: `APP_STORE` (test store and defaults, no Keychain), `APP_SEED`, `APP_SNAPSHOT`, `APP_RENDER=<dir>`,
  `APP_HEADLESS`, `--selftest`. Never test against the real store or Keychain.

## Rules

- Writes carry an `Idempotency-Key`; the offline queue replays them with the same key. Keep queue rules in ReLifeKit.
- The token lives in the Keychain only (`APP_STORE` builds use memory). Never log it.
- Colors, radii, spacing come from `Tokens` and `Space`. No literals in views.
- Words follow the plan glossary: System quests, routines, goals, XP, Lv, Vanguard. The product name is `Brand.name`.
- Commit after each working change, in Conventional Commit form.
